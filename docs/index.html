What the board says

Lift tracks the bare floor, not the tier

The widest gaps sit on the lowest floors (glm-5.3 13% → +75; R1 13% → +67). The narrowest sits on the highest (qwen3.8-max 25% → +38). A flagship can still floor low: step-5-preview floors 21% and lifts +63.

“Flash” means nothing across brands

Same skill, same criteria: glm-4-flash lifts +4, mimo-v2.6-flash lifts +63. Both are flash tiers. Tier names are marketing, not a capability contract.

Stronger models do not make the skill redundant

If capability absorbed the skill, lift would compress toward zero as models get stronger. It does not: every current-gen row is still +38 or higher, and most sit at +55 to +75. The ceiling effect is local — one easy task saturates both arms, the domain tasks still miss at least one skill-unique criterion.

How it is measured

  1. 8 tasks bound to 7 self-authored skills (MIT). Control arm gets the task only; treated arm gets the skill body injected before the task.
  2. 3 trials × 2 arms per task = 24 calls per arm, temperature=0.
  3. Each task carries 1–3 regex criteria; a trial passes only if all of them hit (AND-gate). No model is used to score another model.
  4. lift = treated − control, in percentage points. n=24 is small: read it as directional evidence, not a precise effect size.

What this board is not

Not a model ranking. A low bare floor is not “a bad model” — across 8 narrow tasks, the floor measures how well a model happens to land on these specific criteria. That is not a clean proxy for general capability.

Not an activation study. The treated arm injects the skill body directly. Real harnesses load only metadata and let the model decide whether to activate a skill — this board measures the ceiling of “body present in context”, not the activation rate.

Not free of deviations. Some reasoning models blew the harness’s 60 s guard at default thinking and were run at a reduced setting; those rows say so. Their floor is a property of that setting, not native-max capability.
